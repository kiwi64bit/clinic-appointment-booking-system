→ العودة لتطبيق حجز المواعيد (CABS)

الدليل الشامل لشرح كود مشروع CABS

نظام حجز المواعيد الطبية الكامل باستخدام Vanilla HTML, CSS & JavaScript

مقدمة تقنية: هذا المشروع مبني ليكون تطبيق واجهة أمامية كامل (Pure Front-end) يعمل مباشرة بمجرد فتح index.html في المتصفح بدون أي أدوات بناء (No Build Step) وبدون خادم خلفي (No Backend)، حيث يعتمد على localStorage كقاعدة بيانات محلية، وتشفير كلمات المرور عبر Web Crypto API (SHA-256).
فهرس الأقسام:
  • 1. الهيكل العام ومسارات الملفات
  • 2. ملف الواجهة الرئيسي (index.html)

  • 6. الأمان وتسجيل الدخول والجلسات (js/auth.js)

2. ملف الواجهة الرئيسي (index.html)

يعمل الملف كحاوية لتطبيق الصفحة الواحدة (Single Page Application - SPA):

  • <header id="cabs-header">: يحتوي على الحاوية #header-container التي يرسم فيها ملف app.js شريط التنقل ديناميكياً بحسب دور المستخدم الحالي (مريض، طبيب، أو مسؤول).
  • <main id="main-viewport">: مساحة العرض الرئيسية التي يتم تفريغها وحقن شاشات التطبيق بداخلها فورياً عند تغيير الرابط (Hash Routing).
  • ترتيب تحميل السكربتات: تم ترتيب السكربتات لتجنب أي أخطاء في التبعيات: models.js → storage.js → auth.js → services.js → ui.js → views/*.js → app.js.

3. ملف التنسيق ونظام التصميم (css/styles.css)

تم تصميم التطبيق وفق طابع طبي مريح ونظيف (Clean Medical Aesthetic):

  • لوحة الألوان الأساسية: درجات الأزرق المخضر (Teal & Blue-Green) مثل #0d9488 مع درجات الرمادي المريح للعين.
  • شارات الحالات (Status Badges): Available Booked Blocked Completed Cancelled No-Show
  • التجاوب الكامل (Responsive - NFR-02): متجاوب من شاشات الجوال (375px) إلى الشاشات الواسعة (1280px+) مع وضع الجداول داخل .table-responsive لضمان عدم حدوث أي شريط تمرير أفقي على مستوى الصفحة.
  • إمكانية الوصول (Accessibility): إطار تركيز واضح للمفاتيح عبر :focus-visible وتسميات صريحة لجميع حقول النماذج.

4. نماذج الكائنات (js/models.js)

يحتوي هذا الملف على الكائنات الأساسية (Domain Classes) المطابقة تماماً للمتطلبات:

اسم الصنف (Class) الحقول الأساسية الوصف
User id, email, passwordHash, role, createdAt الصنف الأساسي الذي يرث منه المريض والطبيب والمسؤول.
Patient fullName, email, phone, dateOfBirth, passwordHash يمثل المريض المسجل في النظام.
Doctor name, email, specialtyId, fee, bio, workingDays, consultationHours, active يمثل الطبيب المعالج مع أوقات وساعات الدوام وحالة النشاط.
Administrator id, name, email, passwordHash مسؤول النظام لإدارة المستشفى والتخصصات والأطباء.
Specialty id, name, description التخصص الطبي (مثل القلب، العظام، الأطفال...).
TimeSlot doctorId, date, startTime, endTime, status الفترة الزمنية المحددة للطبيب (Available, Booked, Blocked).
Appointment patientId, doctorId, slotId, date, startTime, endTime, status, notes كائن الموعد المحجوز بحالاته (Booked, Cancelled, Completed, No-Show).

5. قاعدة البيانات والبيانات التجريبية (js/storage.js)

يعمل كطبقة قاعدة بيانات كاملة في المتصفح مع حفظ دائم في localStorage تحت المفتاح CABS_DATA:

اسم الدالة (Function) الوظيفة والشرح التفصيلي
formatDate(d) تحول كائن التاريخ JavaScript Date إلى صيغة نصية قياسية YYYY-MM-DD لتخزينها في المواعيد والفترات.
addDays(d, days) تضيف عدداً معيناً من الأيام (موجب أو سالب) على تاريخ محدد وترجع كائن تاريخ جديد (تُستخدم لبناء جدول الـ 14 يوماً القادمة والأيام الماضية).
generateSeedData() تولد البيانات الأولية الكاملة: 6 تخصصات، 9 أطباء (2 غير نشطين)، 23 مريضاً، فترات زمنية لـ 14 يوماً قادماً، ومواعيد بجميع الحالات (Booked, Cancelled, Completed, No-Show).
Storage.init() تُستدعى عند تحميل الملف؛ تفحص وجود CABS_DATA في المتصفح، وإذا لم يكن موجوداً أو كان تالفاً تستدعي reset() تلقائياً.
Storage.getDB() تقرأ قاعدة البيانات من localStorage وتحولها من JSON إلى كائن JavaScript جاهز للاستخدام.
Storage.saveDB(db) تحفظ الكائن الكامل لقاعدة البيانات داخل localStorage بصيغة JSON بعد أي تعديل (NFR-03).
Storage.reset() تستدعي generateSeedData() وتعيد كتابة قاعدة البيانات الأصلية بالكامل لإلغاء أي تعديلات تجريبية.
Storage.getSpecialties()
getDoctors(), getPatients(),
getAdministrators(),
getTimeSlots(), getAppointments()		 دوال قراءة (Getters) تستخرج المصفوفة الخاصة بكل كيان من قاعدة البيانات بأمان (ترجع مصفوفة فارغة إذا لم توجد بيانات).
Storage.findUserByEmail(email) تبحث عن البريد الإلكتروني (بدون حساسية لحالة الأحرف) عبر جداول المسؤولين ثم الأطباء ثم المرضى، وترجع الكائن مع دوره { user, role }.
Storage.findDoctorById(id)
findPatientById(id),
findSpecialtyById(id),
findTimeSlotById(id),
findAppointmentById(id)		 دوال بحث سريعة تسترجع كائناً واحداً محدداً عن طريق المعرّف الفريد الخاص به (id)، أو ترجع null إذا لم يوجد.

6. الأمان وتسجيل الدخول والجلسات (js/auth.js)

يختص هذا الملف بمتطلبات FR-01, FR-02, FR-03, NFR-04:

اسم الدالة (Function) الوظيفة والشرح التفصيلي
hashPassword(text) دالة غير متزامنة (async) تستخدم window.crypto.subtle.digest('SHA-256', ...) لتحويل كلمة المرور إلى بصمة تجزئة سداسية عشرية من 64 حرفاً، مع بديل احتياطي للبيئات المقيدة.
Auth.registerPatient({ fullName, email, phone, dateOfBirth, password }) (FR-01) تتحقق من اكتمال جميع الحقول، وصحة صيغة البريد الإلكتروني، وطول كلمة المرور (6 أحرف على الأقل)، وتمنع تكرار البريد الإلكتروني عبر findUserByEmail، ثم تشفر كلمة المرور وتحفظ كائن Patient جديد.
Auth.login(email, password) (FR-02) تتحقق من وجود المستخدم ومطابقة البصمة المشفرة لكلمة المرور، وترفض دخول الأطباء غير النشطين، وعند النجاح تحفظ الجلسة في sessionStorage تحت المفتاح CABS_SESSION وترجع مسار لوحة التحكم المناسبة.
Auth.logout() (FR-03) تمسح الجلسة من sessionStorage وتعيد توجيه المستخدم فوراً إلى صفحة الدخول #login.
Auth.getSession() تقرأ بيانات الجلسة الحالية من sessionStorage وترجعها ككائن (أو null إذا لم يكن هناك مستخدم مسجل).
Auth.getCurrentUser() تستخدم بيانات الجلسة الحالية لجلب السجل الكامل للمستخدم (مريض أو طبيب أو مسؤول) من قاعدة البيانات.
Auth.getDefaultRouteForRole(role) تحدد المسار الافتراضي لكل دور: #patient-dashboard للمريض، #doctor-dashboard للطبيب، و#admin-dashboard للمسؤول.
Auth.guardRoute(routePath) (FR-03, NFR-04) حارس المسارات: يمنع غير المسجلين من دخول أي صفحة محمية، ويمنع المسجلين من دخول صفحات لا تخص دورهم، ويحمي التطبيق عند الضغط على زر الرجوع في المتصفح.

الدوال المساعدة العامة (Helpers)

الدالةالشرح

timesOverlap(startA, endA, startB, endB) تفحص تداخل فترتين زمنيتين في نفس اليوم باستخدام المعادلة: startA < endB && startB < endA.

getDoctorProfile(doctorId) (FR-05) تجلب بيانات الطبيب الكاملة مدمجة مع اسم تخصصه specialtyName.

toggleDoctorStatus(doctorId) (FR-15) تعكس حالة الطبيب بين نشط (true) وغير نشط (false) مع الاحتفاظ بكافة مواعيده التاريخية.

updateSpecialty(id, { name, description }) (FR-14) تعدل اسم ووصف التخصص مع منع الفراغ أو التكرار مع تخصص آخر.

createSlot({ doctorId, date, startTime, endTime }) (FR-16) تنشئ فترة متاحة جديدة للطبيب بعد التحقق من أن وقت النهاية بعد البداية وأنه لا يوجد تداخل مع أي فترة أخرى لنفس الطبيب في نفس اليوم.
toggleBlockSlot(slotId) (FR-16) تحول الفترة بين Available وBlocked، وترفض نهائياً حظر أي فترة حالتها Booked.

د. خدمة المواعيد ومنع التعارض (AppointmentService)

الدالةالشرح
validateSlotAvailability(patientId, doctorId, slotId, excludeAppointmentId) (FR-08) قلب النظام لمنع التعارض: تتحقق من أن الفترة موجودة، تتبع الطبيب، حالتها Available، في المستقبل، وأن المريض لا يملك موعداً آخر محجوزاً يتداخل زمنياً معها في نفس اليوم.
bookAppointment({ patientId, doctorId, slotId, notes }) (FR-07) تستدعي validateSlotAvailability، وتتحقق من نشاط الطبيب، ثم تحول الفترة إلى Booked وتنشئ كائن Appointment وتحفظه.
cancelAppointment(appointmentId, cancelledByUserId, reason) (FR-10) تلغي موعداً مستقبلياً حالته Booked، وتغيره إلى Cancelled مع إرجاع الفترة الزمنية إلى Available.
rescheduleAppointment(appointmentId, newSlotId) (FR-11) تفحص الفترة الجديدة عبر validateSlotAvailability أولاً؛ إذا نجحت تحرر الفترة القديمة، وتحجز الجديدة، وتحدث بيانات الموعد، وإذا فشلت تبقي الموعد الأصلي كما هو.
updateVisitStatus(appointmentId, doctorId, newStatus, visitNotes) (FR-13) تتيح للطبيب صاحب الموعد فقط إنهاء الزيارة كـ Completed أو No-Show وإرفاق ملاحظات طبية.
getPatientAppointments(patientId) (FR-09) تجمع مواعيد المريض مع أسماء الأطباء والتخصصات وتقسمها إلى مصفوفتي upcoming وpast.
getDoctorDailySchedule(doctorId, dateStr) (FR-12) تجلب مواعيد الطبيب ليوم محدد مرتبة بالوقت ومرفقة ببيانات المريض (الاسم، الهاتف، البريد).
getAdminAppointments({ date, doctorId, patientId, status }) (FR-17) تجلب كافة المواعيد للمسؤول مع تطبيق الفلاتر الأربعة ودمج بيانات الطبيب والمريض والتخصص.
searchPatients(query) (FR-18) تبحث في قائمة المرضى بالاسم الكامل أو البريد الإلكتروني أو رقم الهاتف.
getPatientRecord(patientId) (FR-18) تجلب الملف الشخصي للمريض مع سجل زياراته الكامل لعرضه في لوحة المسؤول.

8. واجهة التنبيهات والنوافذ (js/ui.js)

الدالةالشرح
UI.showToast(message, type, duration) تنشئ وتعرض إشعاراً فورياً في زاوية الشاشة بأنواع (success, error, warning, info) مع زر إغلاق واختفاء تلقائي بعد المدة المحددة.
UI.showModal({ title, contentHtml, confirmText, cancelText, onConfirm, onCancel, size }) تعرض نافذة حوارية منبثقة احترافية تدعم الإغلاق بزر Escape أو النقر خارج النافذة، وتدير حالة زر التأكيد أثناء التنفيذ.

UI.formatCurrency(amount) تنسق الأرقام كعملة مالية (مثل $120.00).

AdminViews.renderSpecialtiesTab() (FR-14) تعرض التخصصات الطبية مع نوافذ الإضافة والتعديل ومنع التكرار أو الفراغ.

AdminViews.renderPatientsTab() (FR-18) توفر بحثاً فورياً في سجلات المرضى ونافذة منبثقة لعرض بيانات المريض وتاريخ زياراته بالكامل.

الدالةالشرح
parseHash(hashStr) تحلل عنوان الـ Hash (مثل #doctor-profile?id=doc_sarah) وتفصل المسار الأساسي عن معاملات الاستعلام (params).
App.init() تهيئ قاعدة البيانات وتربط مستمعي أحداث المتصفح (hashchange, pageshow, popstate) ثم تشغل الموجه لأول مرة.
App.renderHeader() ترسم شريط التنقل العلوي ديناميكياً حسب حالة تسجيل الدخول ودور المستخدم، وتفعل زر تسجيل الخروج وزر Reset Demo Data.
App.handleRoute() تستدعي Auth.guardRoute للتحقق من الصلاحيات، ثم ترسم الهيدر وتوجه العرض إلى الدالة المناسبة للشاشة المطلوبة وتعيد التمرير لأعلى الصفحة.
